\section{Thiết kế thuật toán}
%========================================

\subsection{Bài toán 1: Tích vô hướng (Dot Product)}
Cho hai vector $A$, $B$ kích thước $N = 1{,}000{,}000$. Tính $\text{Result} = \sum_{i=0}^{N-1} A_i \times B_i$.

\textbf{CUDA -- Parallel Reduction:} Mỗi thread tính $A[i] \times B[i]$, lưu vào shared memory. Thực hiện parallel reduction theo cây nhị phân ($\log_2(256) = 8$ bước) trong từng block (\texttt{BLOCK\_SIZE=256}, \texttt{numBlocks=3907}). Thread 0 ghi block sum ra global memory, host tổng hợp.

\textbf{C\# Thread/Task:} Chia vector thành $P$ chunks ($P$ = \texttt{ProcessorCount}), mỗi Task tính partial sum, kết quả tổng hợp tuần tự.

\textbf{C\# Channel:} Partial sums gửi qua \texttt{Channel<double>}, consumer đọc và cộng dồn (producer-consumer pattern).

\subsection{Bài toán 2: Chuyển vị ma trận ($1024 \times 2048$)}
Tính $A^T$ sao cho $A^T[j][i] = A[i][j]$.

\textbf{CUDA Naive:} Mỗi thread đọc $A[y][x]$ ghi $B[x][y]$ -- coalesced reads nhưng uncoalesced writes.

\textbf{CUDA Shared Memory:} Tile $32 \times 32$ với padding (+1 tránh bank conflicts). Đọc coalesced vào shared memory, ghi coalesced ra output. Grid: $(64, 32)$, Block: $(32, 8)$.

\textbf{C\# Thread/Task \& Channel:} Tương tự bài 1, chia rows thành $P$ chunks.

\section{Kết luận}
%========================================

Qua thực nghiệm trên hai bài toán Dot Product và Matrix Transpose, có thể rút ra các nhận xét sau:

\begin{itemize}
    \item \textbf{CUDA vượt trội rõ rệt:} Dot Product đạt speedup 9.41x, Matrix Transpose đạt 426.12x (shared memory) so với CPU sequential. Massive parallelism trên GPU phù hợp cho cả bài toán compute-bound và memory-bound.
    \item \textbf{Shared memory là kỹ thuật tối ưu quan trọng:} Transpose với shared memory nhanh hơn naive 4.24x nhờ coalesced access và tránh bank conflicts bằng padding.
    \item \textbf{C\# Task/Channel phụ thuộc vào kích thước bài toán:} Với Dot Product ($N = 10^6$ phép đơn giản), overhead tạo Task/Channel lấn át. Nhưng với Transpose ($2 \times 10^6$ phần tử, memory-intensive), Thread/Task đạt 2.45x speedup.
    \item \textbf{Lựa chọn kỹ thuật song song cần cân nhắc:} Channel phù hợp cho kiến trúc producer-consumer phức tạp, Thread/Task phù hợp cho chia dữ liệu đơn giản, CUDA phù hợp khi cần hiệu năng tối đa.
\end{itemize}
